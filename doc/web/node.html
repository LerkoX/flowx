节点与步骤

本文档介绍节点（Node）和步骤（Step）的概念、配置、状态管理以及输出提取功能。

概述

在 FlowX 中，节点（Node）是流水线的基本执行单元，每个节点包含：

  • 一个执行器引用（决定在哪里运行）
  • 一个或多个步骤（Step，按顺序执行）
  • 可选的输出提取配置（将命令输出转为结构化数据）

节点配置

Nodes:
  Build:
    name: "构建应用"                    # 显示名称
    description: "编译并构建镜像"        # 功能描述
    executor: docker                   # 引用的执行器名称
    image: golang:1.21-alpine          # 容器镜像（Docker/K8s）
    steps:                             # 步骤列表
      - name: compile
        run: go build -o app .
      - name: image
        run: docker build -t app:latest .
    extract:                           # 输出提取配置（可选）
      type: codec-block

节点字段

字段类型必填说明
executorstring是引用 Executors 中定义的执行器名称
imagestring否容器镜像（Docker/K8s 执行器使用）
steps[]Step是执行步骤列表
extractobject否输出提取配置
runtimeobject否节点运行时状态（用于恢复）

步骤（Step）

每个节点支持多个步骤按顺序执行。每个步骤的 run 命令在执行时会通过模板引擎渲染，可以引用 Param 和 Metadata 中的值。

Step 字段

字段类型必填说明
idstring否步骤唯一标识（由 EnsureIds() 自动生成）
namestring是步骤名称
descriptionstring否步骤描述
runstring是执行的 shell 命令（支持模板渲染）

多步骤执行示例

Nodes:
  Deploy:
    executor: k8s
    image: bitnami/kubectl:latest
    steps:
      - name: apply
        description: "应用 K8s 资源配置"
        run: kubectl apply -f ./k8s/
      - name: verify
        description: "等待滚动更新完成"
        run: kubectl rollout status deployment/app -n {{ Param.namespace }}
      - name: report
        description: "输出部署信息"
        run: echo "Deployed {{ Param.fullImage }} to {{ Param.namespace }}"

步骤跳过

在恢复执行时，已完成的步骤会被跳过。引擎通过 StepRuntimeStatus 判断步骤状态：

  • 状态为 SUCCESS、FAILED、CANCELLED 的步骤会被跳过
  • 输出日志中会显示 "Skipping step xxx (status: SUCCESS)"

输出提取

输出提取功能可以从命令输出中提取结构化数据，保存到 metadata 中供后续节点使用。提取的数据会自动填充 srcNode 字段。

提取配置

字段类型默认值说明
typestringcodec-block提取类型：codec-block 或 regex
patternsmap-正则表达式（type=regex 时使用）
maxOutputSizeint1048576 (1MB)输出大小限制（字节）

codec-block 模式

识别输出中的 flowx-yaml 代码块并解析，支持行尾注释提取 description。

Nodes:
  Build:
    executor: local
    extract:
      type: codec-block
      maxOutputSize: 1048576
    steps:
      - name: build
        run: |
          echo '```flowx-yaml'
          echo 'version: "1.0.0"  # 版本号'
          echo 'buildStatus: "success"  # 构建状态'
          echo 'imageTag: "myapp:v1.0.0"  # 镜像标签'
          echo '```'

提取后的数据会自动设置 srcNode 为当前节点 ID，并从注释中提取 description。存储到 Metadata 时会添加节点前缀：Metadata["Build.version"]。

regex 模式

使用正则表达式提取内容，每个正则对应一个 key。

Nodes:
  Test:
    executor: local
    extract:
      type: regex
      patterns:
        coverage: "coverage: (\\d+\\.\\d+)%"     # 提取测试覆盖率
        testsPassed: "(\\d+) tests passed"        # 提取通过的测试数
        buildStatus: "Build (\\w+)"               # 提取构建状态
      maxOutputSize: 524288
    steps:
      - name: test
        run: go test -cover

规则：

  • 正则表达式可以包含捕获组，第一个捕获组的内容作为值
  • 如果没有捕获组，使用完整匹配作为值
  • 如果正则无效，创建时返回错误

提取的数据存储

提取的数据会经过转换后存储：

  • 字符串：原样保存
  • slice/map：序列化为 JSON 字符串保存
  • 其他类型：使用 fmt.Sprintf("%v", val) 转换

这使得复杂类型（如数组）可以在后续节点中通过自动解析回对象。

状态管理

节点状态枚举

状态含义
Pending等待执行
Running执行中
SUCCESS执行成功
FAILED执行失败
CANCELLED已取消

运行时状态结构

type NodeRuntimeStatus struct {
    Id         string                  // 运行时 ID
    Status     string                  // 节点状态
    StartTime  time.Time               // 开始时间
    EndTime    time.Time               // 结束时间
    Steps      []StepRuntimeStatus     // 步骤状态列表
    Executor   *ExecutorRuntimeInfo    // 执行器信息
    Custom     map[string]interface{}  // 自定义数据
}

type StepRuntimeStatus struct {
    Id        string        // 步骤 ID
    Name      string        // 步骤名称
    Status    string        // 步骤状态
    StartTime time.Time     // 开始时间
    EndTime   time.Time     // 结束时间
    Error     string        // 错误信息
    Output    string        // 输出内容
}

交互式输入

Local 执行器支持程序主动请求输入。当输出中包含 flowx-input 代码块时，执行器会发出输入请求事件。

输出格式

```flowx-input
prompt: "请输入部署目标"
type: text
timeout: 30
```

输入类型

type说明
text普通文本输入
password密码输入
confirm确认输入（y/n）
