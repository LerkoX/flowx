文件处理工作流

自动化日志管理流水线，包含以下功能：

  • 创建日志文件和归档目录
  • 压缩日志文件
  • 生成归档文件清单
  • 清理超过保留天数的旧文件

特性：并行执行（创建目录、压缩日志、生成清单并行运行）、数据传递（codec-block）、参数化配置。

Version: "1.0"
Name: file-processing

Param:
  projectDir: "/var/log/myapp"
  retentionDays: 30
  archiveDir: "/var/log/myapp/archives"

Executors:
  local:
    type: local
    config:
      shell: bash

Graph: |
  stateDiagram-v2
    [*] --> Setup
    [*] --> Compress
    [*] --> Inventory
    Setup --> Cleanup
    Compress --> Cleanup
    Inventory --> Cleanup
    Cleanup --> [*]

Nodes:
  Setup:
    executor: local
    steps:
      - name: create-dirs
        run: |
          mkdir -p {{ Param.archiveDir }}
          echo '```flowx-yaml'
          echo "setupComplete: true  # 目录创建完成"
          echo '```'
    extract:
      type: codec-block

  Compress:
    executor: local
    steps:
      - name: compress
        run: |
          cd {{ Param.projectDir }}
          tar czf {{ Param.archiveDir }}/logs-$(date +%Y%m%d).tar.gz *.log
          echo '```flowx-yaml'
          echo "compressed: true  # 压缩完成"
          echo '```'
    extract:
      type: codec-block

  Inventory:
    executor: local
    steps:
      - name: list
        run: |
          ls -la {{ Param.archiveDir }}
          echo '```flowx-yaml'
          echo "inventoryComplete: true  # 清单生成完成"
          echo '```'
    extract:
      type: codec-block

  Cleanup:
    executor: local
    steps:
      - name: clean
        run: |
          find {{ Param.archiveDir }} -name "*.tar.gz" -mtime +{{ Param.retentionDays }} -delete
          echo "Cleaned files older than {{ Param.retentionDays }} days"

数据 ETL 工作流

ETL（Extract, Transform, Load）流水线，包含以下功能：

  • 并行采集用户、订单、产品数据
  • 数据格式标准化和转换
  • 生成用户报告和销售报告
  • 合并所有报告
Version: "1.0"
Name: data-etl

Param:
  date: "2024-03-28"
  baseDir: "/data/analytics"
  apiBaseUrl: "https://api.example.com"

Executors:
  local:
    type: local
    config:
      shell: bash

Graph: |
  stateDiagram-v2
    [*] --> FetchUsers
    [*] --> FetchOrders
    [*] --> FetchProducts
    FetchUsers --> Transform
    FetchOrders --> Transform
    FetchProducts --> Transform
    Transform --> GenerateReports
    GenerateReports --> Merge
    Merge --> [*]

Nodes:
  FetchUsers:
    executor: local
    steps:
      - name: fetch
        run: |
          echo "Fetching users for {{ Param.date }}"
          echo '```flowx-yaml'
          echo "usersCount: 1500  # 用户数量"
          echo '```'
    extract:
      type: codec-block

  FetchOrders:
    executor: local
    steps:
      - name: fetch
        run: |
          echo "Fetching orders for {{ Param.date }}"
          echo '```flowx-yaml'
          echo "ordersCount: 3200  # 订单数量"
          echo '```'
    extract:
      type: codec-block

  FetchProducts:
    executor: local
    steps:
      - name: fetch
        run: |
          echo "Fetching products"
          echo '```flowx-yaml'
          echo "productsCount: 500  # 产品数量"
          echo '```'
    extract:
      type: codec-block

  Transform:
    executor: local
    steps:
      - name: transform
        run: |
          echo "Transforming data..."
          echo "Users: {{ .Metadata.FetchUsers.usersCount }}"
          echo "Orders: {{ .Metadata.FetchOrders.ordersCount }}"
          echo "Products: {{ .Metadata.FetchProducts.productsCount }}"

  GenerateReports:
    executor: local
    steps:
      - name: generate
        run: |
          echo "Generating reports..."
          echo '```flowx-yaml'
          echo "reportsGenerated: true  # 报告已生成"
          echo '```'
    extract:
      type: codec-block

  Merge:
    executor: local
    steps:
      - name: merge
        run: echo "All reports merged successfully"

CI/CD 部署工作流

完整的 CI/CD 部署流水线，包含代码构建、测试、质量检查和条件部署。

Version: "1.0"
Name: ci-cd-deployment

Param:
  environment: "staging"
  skipTests: false
  codeCoverageThreshold: 80

Executors:
  local:
    type: local
    config:
      shell: bash

Graph: |
  stateDiagram-v2
    [*] --> Build
    Build --> Test
    Test --> QualityCheck
    QualityCheck --> DeployStaging : {{ QualityCheck.allTestsPassed == true and QualityCheck.codeCoverage >= Param.codeCoverageThreshold }}
    QualityCheck --> SkipDeploy : {{ QualityCheck.allTestsPassed == false or QualityCheck.codeCoverage < Param.codeCoverageThreshold }}
    DeployStaging --> [*]
    SkipDeploy --> [*]

Nodes:
  Build:
    executor: local
    steps:
      - name: build
        run: |
          echo "Building application..."
          echo '```flowx-yaml'
          echo "buildStatus: success  # 构建状态"
          echo '```'
    extract:
      type: codec-block

  Test:
    executor: local
    steps:
      - name: test
        run: |
          echo "Running tests..."
          echo '```flowx-yaml'
          echo "allTestsPassed: true  # 测试是否全部通过"
          echo "codeCoverage: 85  # 代码覆盖率"
          echo '```'
    extract:
      type: codec-block

  QualityCheck:
    executor: local
    steps:
      - name: check
        run: |
          echo "Tests passed: {{ .Metadata.Test.allTestsPassed }}"
          echo "Coverage: {{ .Metadata.Test.codeCoverage }}%"
          echo '```flowx-yaml'
          echo "allTestsPassed: {{ .Metadata.Test.allTestsPassed }}  # 质量检查结果"
          echo "codeCoverage: {{ .Metadata.Test.codeCoverage }}  # 覆盖率"
          echo '```'
    extract:
      type: codec-block

  DeployStaging:
    executor: local
    steps:
      - name: deploy
        run: echo "Deploying to {{ Param.environment }}..."

  SkipDeploy:
    executor: local
    steps:
      - name: skip
        run: echo "Quality checks failed, skipping deployment"

Docker 构建工作流

展示如何使用 Docker 执行器运行完整的 CI 流水线。

Version: "1.0"
Name: docker-build-example

Executors:
  docker-alpine:
    type: docker
    config:
      registry: "docker.io"
      network: bridge
      workdir: /app
      env:
        CGO_ENABLED: "0"

  docker-golang:
    type: docker
    config:
      registry: "docker.io"
      network: bridge
      workdir: /app
      env:
        CGO_ENABLED: "0"
        GOOS: linux
        GOARCH: amd64

Graph: |
  stateDiagram-v2
    [*] --> Checkout
    Checkout --> Build
    Build --> Test
    Test --> Package
    Package --> [*]

Nodes:
  Checkout:
    executor: docker-alpine
    image: alpine:latest
    steps:
      - name: checkout
        run: |
          echo "Checking out code..."
          echo '```flowx-yaml'
          echo "checkoutComplete: true  # 检出完成"
          echo '```'
    extract:
      type: codec-block

  Build:
    executor: docker-golang
    image: golang:1.21-alpine
    steps:
      - name: build
        run: |
          go build -o app .
          echo '```flowx-yaml'
          echo "binary: app  # 构建产物"
          echo '```'
    extract:
      type: codec-block

  Test:
    executor: docker-golang
    image: golang:1.21-alpine
    steps:
      - name: test
        run: go test ./...

  Package:
    executor: docker-alpine
    image: alpine:latest
    steps:
      - name: package
        run: |
          echo "Packaging {{ .Metadata.Build.binary }}..."
          echo "Build complete!"

天气通知工作流

从天气 API 获取信息，通过飞书发送富文本消息通知。

Version: "1.0"
Name: weather-feishu-notify

Param:
  city: "深圳"
  notifyTime: "07:30"
  feishuAppId: "cli_xxx"
  feishuAppSecret: "xxx"
  feishuChatId: "oc_xxx"

Executors:
  local:
    type: local
    config:
      shell: bash

Graph: |
  stateDiagram-v2
    [*] --> FetchWeather
    FetchWeather --> SendNotification
    SendNotification --> [*]

Nodes:
  FetchWeather:
    executor: local
    steps:
      - name: fetch
        run: |
          echo "Fetching weather for {{ Param.city }}..."
          echo '```flowx-yaml'
          echo "temperature: 25  # 当前温度"
          echo "condition: 晴  # 天气状况"
          echo "humidity: 60  # 湿度"
          echo '```'
    extract:
      type: codec-block

  SendNotification:
    executor: local
    steps:
      - name: send
        run: |
          echo "Sending notification to Feishu..."
          echo "City: {{ Param.city }}"
          echo "Temperature: {{ .Metadata.FetchWeather.temperature }}°C"
          echo "Condition: {{ .Metadata.FetchWeather.condition }}"
          echo "Notification sent!"

运行方式

方法一：使用 Go 库

package main

import (
    "context"
    "fmt"
    "os"

    "github.com/LerkoX/flowx"
)

func main() {
    ctx := context.Background()

    // 加载配置文件
    configData, err := os.ReadFile("file_processing.yaml")
    if err != nil {
        fmt.Printf("读取配置文件失败: %v\n", err)
        os.Exit(1)
    }

    // 创建运行时
    runtime := flowx.NewRuntime(ctx)

    // 运行流水线
    pipelineID := "my-pipeline"
    pipeline, err := runtime.RunSync(ctx, pipelineID, string(configData), nil)
    if err != nil {
        fmt.Printf("流水线执行失败: %v\n", err)
        os.Exit(1)
    }

    fmt.Printf("流水线 %s 执行完成！状态: %s\n", pipeline.Id(), pipeline.Status())
}

方法二：直接运行 YAML

// 将 YAML 内容作为字符串传入
configYAML := `

关键特性说明

特性说明
数据传递使用 flowx-yaml 代码块或 regex 提取数据，通过 {{ .Metadata.NodeName.fieldName }} 引用
并行执行在 Graph 中定义多个并发的边即可实现并行
条件边使用模板表达式实现条件分支
参数化配置使用 {{ Param.key }} 在模板中引用参数
