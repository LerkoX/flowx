流水线核心

本文档介绍 FlowX 的核心流水线机制：DAG 图结构、统一遍历算法（支持有环/无环图）、循环执行、暂停恢复、动态图修改和事件系统。

概述

FlowX 的流水线基于 DAG（有向无环图）结构组织任务。每个节点代表一个执行单元，边代表执行顺序和依赖关系。引擎使用 BFS 层级遍历算法，支持无环图和有环图（通过条件回边实现循环）。

流水线执行流程： Run() 被调用 ├── 触发 PipelineStart 事件 ├── 创建求值上下文（EvaluationContext） ├── 逐层 BFS 执行（runLevelByLevel） │ ├── 循环开始： │ │ ├── 设置 iteration 到求值上下文 │ │ ├── 计算 BFS 层级（使用 forwardGraph） │ │ └── 逐层执行： │ │ ├── 检查暂停信号 → 保存层级，等待恢复 │ │ ├── 检查取消信号 → 返回 ctx.Err() │ │ ├── 并发执行当前层级所有节点 │ │ └── 重新计算后续层级（条件边可获取最新 metadata） │ └── 循环检测： │ ├── 无回边 → 返回（无环图） │ ├── 评估回边条件 → true → 重置循环节点，继续迭代 │ └── 评估回边条件 → false → 循环结束 ├── 清理所有执行器 ├── 触发 PipelineFinish 事件 └── 关闭 doneChan

DAG 图结构

FlowX 使用 Mermaid stateDiagram-v2 语法定义图结构。引擎解析此语法后，自动创建节点和边。

基本图结构

Graph: |
  stateDiagram-v2
    [*] --> Build
    Build --> Test
    Test --> Deploy
    Deploy --> [*]

上述配置定义了三个节点：Build → Test → Deploy，按顺序执行。

并行图结构

Graph: |
  stateDiagram-v2
    [*] --> Task1
    [*] --> Task2
    [*] --> Task3
    Task1 --> Merge
    Task2 --> Merge
    Task3 --> Merge
    Merge --> [*]

上述配置中，Task1、Task2、Task3 没有相互依赖，会并行执行。当三个任务都完成后，Merge 才会执行。

统一 BFS 遍历算法

FlowX 的 Traversal 和 TraversalSteps 使用同一套 BFS 层级计算逻辑，有环图和无环图无需区分代码路径。

无环图遍历

  1. 构建 forwardGraph（无环图等同于原始图）
  2. 计算 forwardGraph 中所有节点的入度
  3. 入度为 0 的节点作为起始节点
  4. 并发执行所有入度为 0 的节点
  5. 节点执行完成后，评估其所有出边
  6. 条件为 true 或无条件的边：将目标节点入度减 1
  7. 重复步骤 4-6，直到所有节点执行完毕
示例：Build → Test → Deploy 起始节点: [Build] 入度: Build=0, Test=1, Deploy=1 ↓ Build 完成 层级 2: [Test] 入度: Test=0, Deploy=1 ↓ Test 完成 层级 3: [Deploy] 入度: Deploy=0

有环图遍历

有环图通过 forwardGraph + 回边评估 实现循环执行：

  1. forwardGraph：排除所有回边后的邻接表
  2. 层级计算：在 forwardGraph 上执行 BFS，得到拓扑层级
  3. 逐层执行：按层级执行所有节点
  4. 回边评估：所有层级执行完毕后，评估回边条件
    • 条件为 true → 重置循环节点的运行时状态，从头开始下一轮迭代
    • 条件为 false → 循环结束
  5. 迭代安全：通过 MaxLoopIterations（默认 100）防止无限循环
图结构: A → B → C → D，回边 C → A（条件: iteration < 3） 迭代 0: A → B → C → D → 评估回边 C→A: iteration(1) < 3 → true 迭代 1: A → B → C → D → 评估回边 C→A: iteration(2) < 3 → true 迭代 2: A → B → C → D → 评估回边 C→A: iteration(3) < 3 → false → 结束
注意：评估回边时使用的是 iteration + 1（预判下一次迭代），因此 iteration < 3 实际执行 3 轮（iteration 0、1、2）。

循环执行

通过条件回边实现可控循环，使用内置 iteration 变量控制迭代次数。

MaxLoopIterations: 5

Graph: |
  stateDiagram-v2
    [*] --> A
    A --> B
    B --> C
    C --> A: {{ iteration < 3 }}
    C --> D
    D --> [*]
迭代轮次执行的节点评估 C→A 时 iteration 值结果
0A→B→C→D1true，继续循环
1A→B→C→D2true，继续循环
2A→B→C→D3false，循环结束

流水线生命周期

状态流转

Init → Running → Success → Failed → Cancelled → Paused → Running (恢复) → Stopped → Running (恢复)

节点跳过机制

节点和步骤在以下终端状态下会被跳过：

  • SUCCESS - 已成功完成
  • FAILED - 已失败
  • CANCELLED - 已取消

这使得快照恢复成为可能：导出当前状态后重新加载配置，已完成的节点不会重复执行。

取消机制

调用 Cancel() 会取消流水线的 context，进而：

  1. 所有正在运行的执行器收到取消信号
  2. 执行器终止当前进程
  3. 节点状态更新为 CANCELLED
  4. 流水线状态更新为 CANCELLED

并发执行

同一层级内的节点通过 goroutine 并行执行，层级之间串行执行。这是 FlowX 实现高效流水线的基础。

Graph: |
  stateDiagram-v2
    [*] --> FetchUsers
    [*] --> FetchOrders
    [*] --> FetchProducts
    FetchUsers --> Merge
    FetchOrders --> Merge
    FetchProducts --> Merge
    Merge --> [*]

在这个例子中：

  • 层级 1：FetchUsers、FetchOrders、FetchProducts 并行执行
  • 层级 2：三个任务都完成后，Merge 执行

暂停与恢复

暂停流水线

调用 Pause() 后，流水线会在当前层级的所有节点执行完成后暂停：

pipeline, _ := rt.RunAsync(ctx, "pipeline-001", config, nil)

// 暂停（等待当前层执行完毕）
err := pipeline.Pause()

恢复流水线

err := pipeline.Resume(ctx)

恢复后会重新计算 BFS 层级（图可能已被修改），从暂停时的层级继续执行。

动态图修改

在流水线处于 PAUSED、STOPPED、FAILED、CANCELLED 或 SUCCESS 状态时，可以通过 Runtime.ModifyGraph 修改图结构。

mods := flowx.GraphModifications{
    RemoveNodes: []string{"OldNode"},
    AddNodes: []flowx.NodeConfig{
        {
            Name:     "NewNode",
            Executor: "local",
            Steps: []flowx.Step{
                {Name: "step1", Run: "echo hello"},
            },
        },
    },
    AddEdges: []flowx.EdgeModification{
        {Source: "NewNode", Target: "ExistingNode"},
    },
}

err := rt.ModifyGraph(ctx, "pipeline-001", mods)

修改操作是原子的：如果任何一步失败，会自动回滚到修改前的状态。

修改操作顺序

  1. 删除边
  2. 删除节点（自动删除关联边）
  3. 添加新节点
  4. 添加新边
  5. 解析 Mermaid 图片段（如果有）
  6. 校验图结构（允许条件回边，拒绝无条件环）
  7. 更新存储的配置
  8. 触发 PipelineGraphModified 事件

事件系统

FlowX 提供完整的生命周期事件系统，支持自定义监听器。

事件常量值触发时机
EventPipelineInitPipelineInit流水线初始化
EventPipelineStartPipelineStart流水线开始执行
EventPipelineFinishPipelineFinish流水线执行完成
EventPipelineNodeStartPipelineNodeStart节点开始执行
EventPipelineNodeFinishPipelineNodeFinish节点执行完成
EventPipelinePausedPipelinePaused流水线暂停
EventPipelineResumedPipelineResumed流水线恢复
EventPipelineCancelledPipelineCancelled流水线被取消
EventPipelineStatusUpdatePipelineStatusUpdate流水线状态更新
EventPipelineGraphModifiedPipelineGraphModified图被动态修改

更多事件相关内容参见 事件系统 文档。
