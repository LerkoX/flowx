快速开始

本指南将带你从零开始，在 5 分钟内运行你的第一个 FlowX 流水线。

1

安装

FlowX 需要 Go 1.23 或更高版本。使用 go get 安装：

go get github.com/LerkoX/flowx

验证安装：

go list -m github.com/LerkoX/flowx
2

创建第一个流水线

创建项目目录并初始化 Go 模块：

mkdir my-flowx-project && cd my-flowx-project
go mod init my-flowx-project

创建 main.go 文件：

package main

import (
    "context"
    "fmt"
    "github.com/LerkoX/flowx"
)

func main() {
    ctx := context.Background()

    // 1. 创建运行时
    rt := flowx.NewRuntime(ctx)

    // 2. 准备 YAML 配置
    configYAML := `
Version: "1.0"
Name: hello-pipeline

Executors:
  local:
    type: local
    config:
      shell: bash

Graph: |
  stateDiagram-v2
    [*] --> Hello
    Hello --> [*]

Nodes:
  Hello:
    executor: local
    steps:
      - name: greet
        run: echo "Hello, FlowX!"
`

    // 3. 同步执行
    p, err := rt.RunSync(ctx, "hello-001", configYAML, nil)
    if err != nil {
        panic(err)
    }

    // 4. 等待完成并输出状态
    <-p.Done()
    fmt.Println("Pipeline status:", p.Status())
}
3

理解配置结构

上面的 YAML 配置包含四个核心部分：

字段作用
Executors定义执行器，这里注册了一个名为 local 的本地 Shell 执行器
Graph使用 Mermaid stateDiagram-v2 定义节点执行顺序
Nodes定义每个节点使用的执行器和执行的步骤
Param / Metadate可选，定义全局参数和元数据存储（本示例未使用）
提示：Graph 中的 [*] 表示起始和结束节点，FlowX 会自动处理它们。节点名称（如 Hello）必须与 Nodes 下的键名一致。
4

运行

go run main.go

预期输出：

Hello, FlowX!
Pipeline status: SUCCESS

恭喜你！你的第一个 FlowX 流水线已经成功运行。

常见问题

Q: 如何查看执行日志？

FlowX 默认将日志输出到控制台。你也可以设置自定义的 Pusher 将日志推送到外部系统：

pusher := logger.NewConsolePusher()
rt.SetPusher(pusher)

Q: 异步执行和同步执行有什么区别？

  • RunSync：阻塞当前 goroutine，直到流水线完成
  • RunAsync：在后台 goroutine 执行，立即返回 Pipeline 实例，通过 <-p.Done() 等待完成

Q: 流水线 ID 可以重复吗？

不可以。同一个 Runtime 中，流水线 ID 必须唯一。如果需要重新运行，先调用 rt.Rm(id) 移除旧记录，或使用新的 ID。
